# Produce Teaching Video

Turn source material into a video that changes what the intended learner can explain or do. Preserve the user's subject, audience, platform, style, tools, and authorization boundaries.

For a new lesson, read [references/lesson-design.md](references/lesson-design.md) before locking the brief. For an existing lesson, read its production status first and resume from the last durable checkpoint.

## Route the work

- Read [references/production-workflow.md](references/production-workflow.md) when starting, resuming, or completing production.
- Read [references/artifacts.md](references/artifacts.md) when creating or repairing an episode structure or handoff.
- Read [references/multi-role-audio.md](references/multi-role-audio.md) only when multiple speakers have non-contiguous lines.

## Preserve the teaching contract

One video should establish one coherent mental model or procedural ability. Record the audience's prerequisite knowledge, likely wrong prediction or failure point, the observable outcome, the model's limits, and one transfer task before script lock.

Use sources appropriate to the subject. Separate verified facts, demonstrated evidence, interpretation, and idealization. Mark missing claims `needs_source` and missing legal media `needs_asset`; never fill either gap from memory or a generated image.

Prefer this learning sequence when it fits: predict or attempt, observe the relevant change, freeze a comparison, explain in ordinary language, introduce the precise term or step, then apply it to a nearby case. Do not open with generic course framing when a concrete problem can establish the need.

Keep spoken words, speaker/performance direction, and visual action in separate artifacts. Generate or import continuous narration before locking captions and motion timing. Derive the timeline from the accepted audio, never from character count.

Use `persona`, `evidence`, and `model` as semantic roles rather than a mechanical rotation. Exact relationships—measurements, equations, code output, interface states, maps, timelines, graphs, procedures, or causal steps—must be produced from verified data or deterministic construction. Generative media may support atmosphere or an authorized character, but must not invent evidence or decide the relationship being taught.

## Enforce durable gates

Do not skip `brief-locked`, `script-locked`, `audio-locked`, `alignment-locked`, `visual-plan-locked`, `keyframes-locked`, `sample-approved`, and `final-qc-passed` when those stages apply.

Before paid services, image generation, dependency installation, external upload, final rendering, or publication, verify that the current task already authorizes that exact action. Permission to make a local draft never implies publication.

Make a representative sample before the full render. It must contain the core teaching interaction, every active visual role, and a real transition. Approve it only after subject accuracy, source traceability, timing, captions, accessibility, and the learner transfer task pass.

After each meaningful stage, update the status with locked artifacts, sources, checks, unresolved issues, authorization scope, next action, and rollback path. Treat project files—not chat history—as durable production memory.
