两个分支改了同一行，Git 突然停止合并。它是不是坏了？不是。它只是发现了两份不同答案，无法替你判断哪一份符合真正需求。

先运行 git status，找到标为 both modified 的文件。打开它，HEAD 到分隔线之间是当前分支的内容，分隔线到另一端是正在合入的内容。

不要一看到 ours 或 theirs 就盲选。先弄清两次修改各自想解决什么，再把冲突区域改成真正要保留的最终文本，并删掉所有冲突标记。

接着检查文件，运行 git add，告诉 Git 这个冲突已经解决；再用 git merge --continue 完成合并。

如果你不想继续，而且合并前工作区是干净的，可以用 git merge --abort 尝试回到合并前。

记住：Git 能指出冲突位置，决定最终含义的是人。

现在换你判断：两个分支各自改对了同一行的一部分，应该整段选一边，还是写出满足两边意图的新版本？答案是先确认意图，再写出新的最终版本。
